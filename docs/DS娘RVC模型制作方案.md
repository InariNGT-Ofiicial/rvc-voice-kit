# DS娘 RVC 音色模型制作方案

> 目标：把「DS娘 · 晓伊 A3」这个**只有 13.944 秒参考音**的 TTS 音色，做成一个能吃干声的 RVC v2 换声模型。
> 本机环境：RVC 2.3.260718 / RTX 5060 Laptop 8 GB / torch 2.7.1+cu128 / 代码源 `rvc-voice-kit`。
> 本文所有数字都是本机实测，不是估算；没测的会明说「未验证」。

---

## 0. 一句话结论

**14 秒参考音不是瓶颈，因为它根本不是训练数据。**

`reference.wav` 只是「晓伊 A3」这个音色的**一张身份证**，它的原始生成器是 `zh-CN-XiaoyiNeural`（Edge 神经 TTS，rate −5%）。
音色的定义权在 **voice ID**，不在那 14 秒——只要还能调用同一个 voice，就能合成出无穷多**同源、零漂移**的语料。

所以推荐路线是：

```
zh-CN-XiaoyiNeural（同源重合成 300 句 → 279 条 / 24.1 min）
        → 切片/归一/质检
        → RVC v2 48k 训练 150 epoch
        → DS娘 RVC 换声模型
```

− 参考音 14 s 的问题被完全绕开（不需要它训练，只需要它当听感锚与 LTAS 参考）。
+ 代价是一个**物理上限**：XiaoyiNeural 是 24 kHz 声源，训出来的模型 15 kHz 以上是数字静音，输出必然带「24k 带宽指纹」。这一条无法通过加数据解决，第 7 节给了判定方法。

## 1. 目标音色的物理事实（先量清楚，再谈方案）

| 项 | 值 | 来源 |
|---|---|---|
| 参考音 | `<PRESETS>\DS娘_晓伊A3\reference.wav` | preset.json |
| 时长 / 采样率 / 声道 | 13.944 s / 24 kHz / 单声道 / PCM_16 | 实测 `sf.info` |
| 峰值 | **0.531**（没有归一化到 -1 dBFS） | 实测 |
| 原始引擎 | `zh-CN-XiaoyiNeural`，本地 `gen_tts.py`，**rate −5%** | preset.json `reference.source` |
| 现有短样本 | 5 条，1.92–3.90 s，共 14.48 s | preset.json `samples` |
| 参考音 + 短样本合计 | **28.4 s** | 相加 |

**关键推论**：28 秒里没有任何一句是「为了训练」录的。全部是同一 TTS 引擎、同一 voice、同一语速的输出 ⇒ 它们在声学上是**同一个点**，不是分布。
把它们当训练集训 RVC，得到的不是「像晓伊A3 的模型」，而是「记住了这 28 秒的模型」——换任何新句子都会崩。

⇒ 必须先解决「数据从哪来」，而这件事只有一条干净答案：**回到同一台 TTS 去批量重合成**。

## 2. 数据来源对比

四条路，逐项给判据。**音色纯度**定义：与 `reference.wav` 的声学一致性（同 voice、同语速、同前端）。**可获取时长**是「不重复、不注水」的真实可用量。

| 方案 | 音色纯度 | 表现力 | 可获取时长 | 风险 | 结论 |
|---|---|---|---|---|---|
| **A. XiaoyiNeural 同源重合成** | ★★★★★ 同一个 voice 参数，实测**逐比特可复现** | ★★☆ 单一。只有一种「平静讲解」腔，无情感起伏 | ★★★★★ 理论上无限；实测 300 句 → 279 条 / 24.1 min，150 s 合成完，零成本 | 声学条件高度同质（同一引擎、同一房间=无房间），泛化到真人输入有韵律风险；24 kHz 带宽上限 | **主训练集** |
| **B. CosyVoice2-0.5B zero-shot** | ★★★ 每次合成**有漂移**（实测见 2.3） | ★★★★ 有情感、有语气指令、能读长句 | ★★★★ 无限，但慢（0.52× 实时） | 漂移样本混入 ⇒ 目标音色分布被拉宽；且它克隆的是 reference.wav 的 14 秒，本身又引入一层不确定性 | **只做交叉验证集 + 情感实验**，不进主训练集 |
| **C. A+B 混合（按比例混）** | ★★ 掺入漂移 | ★★★ | ★★★★ | 最坏的组合：既没有 A 的纯度，也没有 B 的稳定情感。RVC 会把两种音色平均成一个「谁都不像」的中间人 | **不做** |
| **D. 真人补录** | ☆ 没有人能模仿 XiaoyiNeural；真人录出来的就是另一个音色 | ★★★★★ | 0（本机没有可用的 DS娘 真人素材） | 音色直接跑偏，等于换了个角色；版权也不清 | **不做** |

### 2.1 为什么 A 是唯一干净解（实测证据）

Edge TTS 对同一句、同一参数是**完全确定性**的：

```
同一句 × 3 次（t0 / t1 各 3 take）：
  LTAS 两两相关   r = 1.0000, 1.0000, 1.0000
  f0 中位数        280.8 / 280.8 / 280.8 Hz（差 0.00 半音）
  文件内容         np.array_equal == True（逐样本相同）
```

⇒ 用 A 合成 300 句，训练集里只有**一个**音色点，分布宽度 = 0。这正是 RVC 想要的。

### 2.2 表现力单一到什么程度

XiaoyiNeural 只有一个「平静、偏播报」的默认风格，`rate`/`pitch`/`volume` 可以调，但没有情感标签。
实测语速：**约 4.4 汉字/秒**（rate −5%），与 `reference.wav` 一致。

这意味着：**模型学到的「DS娘」只有一种腔调**。要做「惊讶/生气/低语」，靠的不是这个模型，而是喂给它的**输入干声**——RVC 在 `pitch 0` 下是「搬运 f0 与时长、只换音色」，韵律来自源。
⇒ **表现力上限 = 输入干声的表现力**。这是 RVC 的机制，不是本方案的缺陷，但必须写进预期。

### 2.3 CosyVoice2 的漂移有多严重（实测证据）

同一句文本，只改 `torch.manual_seed`，连跑 3 次：

| 句 | LTAS 两两 r | f0 中位数（3 take） | 半音极差 |
|---|---|---|---|
| t0 | 0.9732 / 0.9837 / 0.9799 | 278.4 / **225.5** / 228.8 Hz | **3.65 半音** |
| t1 | 0.9646 / 0.9621 / 0.9888 | 319.8 / 314.3 / 305.3 Hz | 0.80 半音 |

t0 的第 2 个 take 整体掉了 3.65 个半音——那不是「音色微调」，是**换了一个发声区**。
把这种样本混进训练集，RVC 会同时学「278 Hz 的晓伊」和「225 Hz 的晓伊」，输出变成两者平均，听感是一种没有辨识度的中音。

**结论**：B 不能用于训练集。但它的**漂移**恰好使它成为理想的**交叉验证集**——因为它和训练集不同源，能测出真泛化（见第 6.2 节）。

### 2.4 一条被排除的通道：`edge-tts 7.2.8` 直接报 403

本机 CosyVoice env 里的 `edge-tts 7.2.8` 在 WSS 握手时返回：

```
WSServerHandshakeError: 403, url='wss://speech.platform.bing.com/...&Sec-MS-GEC-Version=1-143.0.3650.75'
```

**这不是网络问题**：同一时刻 `list_voices()` 正常返回 322 个音色，`curl https://speech.platform.bing.com/` 返回 400（可达），系统时钟与服务器差 1 秒内。
真实原因是**客户端版本太旧**，`Sec-MS-GEC-Version` 被服务端拒绝。换成 `edge-tts 7.3.1` 后**直连即可成功**（代理与直连都通，单句 1.4–2.8 s）。

⇒ 落地要求：`edge-tts >= 7.3.0`。这条坑的报错信息完全不像版本问题，值得写进踩坑清单。

## 3. 数据量测算

### 3.1 基准：芳乃（已训成、已验收）

| 项 | 值 | 来源 |
|---|---|---|
| 源文件 | 358 个 wav，44.1 kHz，**24.82 min** | 实测目录 + manifest |
| 单条时长 | mean 4.16 s，median 3.82 s，p10–p90 = 1.92–7.02 s | 实测 |
| 切片（3.7 s 窗） | **445 片**，切片总时长 **18.56 min**（产出率 75%） | `logs/fangno_p2/1_16k_wavs` 实测 |
| 切片质量 | **155 片 (35%) < 2 s**，23 片 < 1 s | 实测 |
| 训练 | v2 / 48k / if_f0=1 / bs=4，e120 = 13440 步 | manifest |
| 耗时 | 1.09 min/epoch；e120 ≈ 2.2 h，e200 ≈ 4.35 h | manifest |

**两条可复用的结论**：
1. **切片产出率 ≈ 20 片 / 分钟源音频**（芳乃 17.9，探针 22.3）。
2. **RVC 的 3.7 s 切片器会留下约 35% 的 <2 s 碎片**——这是上游行为，不是数据问题（芳乃也有）。想减少碎片就只能让句子本身落在 3.0–3.7 s。

### 3.2 本次实测（小探针 + 全量各跑一遍，用于外推）

| 项 | 探针（40 句） | 全量（300 句） |
|---|---|---|
| 有效 wav | 35 条（丢 5） | **279 条（丢 21）** |
| 源音频 | 2.78 min，mean 4.77 s | **24.11 min，mean 5.18 s，p50 5.36，p90 7.62** |
| 切片 | 62 片，2.92 min，median 3.62 s，31% <2 s | **529 片，25.27 min，median 3.70 s，25% <2 s，265 片满窗** |
| 训练速度 | 8.39 s/epoch | 外推（未跑满） |
| 单点成本 | **0.135 s / 切片 / epoch** | 同 |

用 0.135 反算芳乃：445 片 × 0.135 = 60 s/epoch，与 manifest 的 65 s/epoch 吻合 ⇒ 该系数可外推。
全量 529 片 × 0.135 = 71 s/epoch ⇒ 150 epoch ≈ **3.0 h**。

> 附带发现：`mean 5.18 s/句` 比「14.4 字 ÷ 4.4 字/秒 = 3.3 s」长 57%。原因是**枚举句的顿号会带停顿**（`苹果、铁路、豆浆。` 实际读 5 s 而不是 3.3 s）。这条直接影响句长设计——按字数估时长会系统性低估。

### 3.3 两档建议（数字来自本次实测，不是估算）

实测换算率：**300 句语料 → 279 条有效 wav（丢 21 条 <1 s）→ 24.11 min → 529 片切片**。
即 **0.086 min / 句**、**1.9 片 / 句**、**22 片 / 分钟源音频**。

| 档 | 源音频 | 句数 | 切片 | 150 epoch 训练 | 说明 |
|---|---|---|---|---|---|
| **最少可行** | **10 min** | **≈ 120 句** | ≈ 220 片 | **≈ 75 min** | 音色能立住、音素覆盖 95%+；韵律多样性明显不足，真人长句输入时容易出怪停顿 |
| **推荐** | **24 min** | **300 句** | **529 片** | **≈ 3.0 h** | 与芳乃同量级（24.8 min / 445 片），且切片质量更好（<2 s 碎片 25% vs 芳乃 35%） |

依据：
- 切片 220 是「每片被充分采样」的下限（bs=4 × 150 epoch = 600 步 × 4 = 2400 样本 ≫ 220）。
- 529 片 ≈ 芳乃实测 445 片，是「已知能训出可用模型」的规模，不需要重新赌。
- **继续加到 60 min 收益很低**：数据是 TTS 合成的，同质性不随长度下降，只增加音素组合；音素覆盖在 300 句时已达 **357/357 饱和**（4.1 节），再加只是重复。

## 4. 语料设计

不能随便抓句子。三件事必须显式设计，否则训出来的模型会在某些字上系统性出错。

### 4.1 音素覆盖（声母 + 韵母）

- 目标集 = jieba `dict.txt` 词频前 4000 词里出现的**无调音节**，共 **357 个**（中文约 410 个基础音节，357 覆盖了高频部分）。
- 算法：先铺 73 条手写自然句 → 贪心补齐没覆盖的音节 → 再补一轮「音节 × 调号」（只补词频前 400 的音节，避免为冷僻字写怪词）。
- 补覆盖用的载体是**枚举句**：`簪子、攒动、暂时、悄悄、技巧、峭壁。`——一句塞 6 个词，读起来是正常列举，不会像生造句那样把 TTS 逼出怪语调。
- 实测结果（300 句）：**357/357 音节全覆盖，不加权 1.000、按词频加权 1.000**；高频音节四声齐全 117/357。
  200 句时为 0.997（差 1 个冷僻音节）——300 句是覆盖饱和点。

> 为什么不追求 357/357：剩下那 1 个音节只出现在极冷僻字里，为它硬造句子会让 TTS 读错（多音字），反而制造脏数据。

### 4.2 句长分布（这条最容易做错）

RVC 的切片窗是 **3.7 s**。句子长度直接决定切片质量：

| 句长 | 时长 | 后果 |
|---|---|---|
| < 1 s | — | 切片留不住，白合成（本次探针丢了 5/40 条） |
| 1.4–2.5 s | 3–8 字 | 能训，但每片 < 3.7 s，训练时被 pad，效率低 |
| **3.0–3.7 s** | **13–16 字** | **一片一句，最干净** |
| 4–7 s | 18–30 字 | 切 2 片，第二片常是碎片 |
| > 8 s | > 35 字 | 切 2–3 片，边界随机，气口被切断 |

实现方式：枚举句的「每行词数」不是固定的，而是从 `[5,6,6,7,7,8,8,9,10,11]` 抽样（每行只抽一次）。
实测输出分布：众数 **16 字（≈3.6 s）**，12–16 字占 52%，同时保留 1–3 字的极短句（给句调与语气词）。

### 4.3 特殊读法（TTS 与 HuBERT 的高危区）

手写句里强制覆盖，每类 6–9 条：

| 类别 | 例 | 为什么必须有 |
|---|---|---|
| 数字/年份/小数/百分比 | `误差只有百分之零点三。` `总共花了八百六十五块钱。` | 数字转写是 TTS 前端最常出错的地方，错一次就是一整类音素缺失 |
| 英文混读 | `这个文件是 PDF 格式的。` `这个 bug 我复现了三次。` | 中英切换处容易出停顿异常；HuBERT 对混读边界敏感 |
| 标点/语气 | `我……好像忘了带钥匙。` `等等——你先别说话。` `她读完了《城与墙》的最后一页。` | 省略号/破折号决定气口长度；书名号会被读成「书名号」以外的停顿 |
| 齿音/塞擦音密集 | `四十四只石狮子。` `知道就是知道，不知道就是不知道。` | zh/ch/sh/z/c/s 是中文 TTS 最含糊的地方，换声后最容易糊成一团 |
| 轻声/儿化/变调 | `孩子们在院子里玩。` `慢慢儿来，不着急。` `姑姑和叔叔都来了。` | 不出现 ⇒ 模型不会处理轻声，输出全是重读，机器味加倍 |

### 4.4 生成量

- 默认 `--sentences 300`：73 条手写 + 227 条枚举（覆盖用 179 + 补调 + 凑数）。
- `--sentences 200` 覆盖 0.997（差 1 个音节），`--sentences 300` 覆盖 1.000。**300 是推荐值**（实测 24.1 min / 529 片）。
- **不要**为了凑时长重复同一批句子。同句重复不增加音素组合，只增加过拟合。

## 5. 完整数据链（命令级）

### 5.0 前置：装对 edge-tts

```bash
# 版本必须 >= 7.3.0（7.2.8 会 403）
<PY> -m pip install "edge-tts>=7.3.0"
```
本次实测用的是隔离安装（`--target`）到 `<ROOT>/_edgetts_probe/lib`，通过 `PYTHONPATH` 注入，没有污染任何现有 env。

### 5.1 语料生成

★ 需要 `pypinyin`，本机只在 CosyVoice env 里有。注意那个 python 是 **3.10、没有 `tomllib`**，`rvcx.paths` 读不到 `rvcx.local.toml`（`COSY=None`）——脚本已对此做了特判（直接问 `jieba.__file__`）。

```bash
cd <WORKSPACE>/rvc-voice-kit
<COSY_ENV>/Scripts/python.exe scripts/dataset/gen_corpus.py \
    --out <ROOT>/corpus/dsxiaoyi_a3 --sentences 300 --seed 20261026
```

产物：`text.txt`（一行一句）、`corpus.jsonl`、`coverage.json`。

### 5.2 批量合成（主训练集）

```bash
<COSY_ENV>/Scripts/python.exe scripts/dataset/synth_corpus.py \
    --backend edge --voice zh-CN-XiaoyiNeural --rate -5% \
    --texts <ROOT>/corpus/dsxiaoyi_a3/text.txt \
    --out <ROOT>/dataset/dsxiaoyi_a3 --workers 4
```

脚本内置的处理顺序（每一步都能在 manifest 里查到数字）：

```
mp3(24k/48kbps) → soundfile 解码
  → ① dtype 闸：峰值 > 4 判为 int16 量级，/32768；> 1 判为超幅 float，按峰值归一
  → ② 去直流
  → ③ 首尾静音修剪（20 ms 帧，−45 dB 相对峰值，留 30 ms padding）  ← 实测每条能砍掉 ~1.0 s 边缘静音
  → ④ 响度归一：目标 −20 dBFS RMS
  → ⑤ 限峰 0.95：若归一后峰值超限，按峰值反算（宁可 RMS 略低，绝不削顶）
  → ⑥ 峰值/削顶/直流/最短时长 四道判据 → ok / drop / fail
  → PCM_16 24 kHz 单声道，一条一个文件
```

**写盘前三道闸的意义**（历史坑，见 `docs/踩坑清单.md` C-19）：TTS 返回 int16 量级数组时按 float 写 PCM_16 会硬削顶，削顶谐波污染 HuBERT，换声后 CER 直接 1.0。本次 300 句全部 `削顶样本 0`、`量级修正 0 条`——因为 edge 的输出本来就是合法 float。

### 5.3 交叉验证集（**必做**，见 6.2）

```bash
RVCX_COSY="<COSY>" \
RVCX_COSY_REF="<PRESETS>/DS娘_晓伊A3/reference.wav" \
<COSY_ENV>/Scripts/python.exe scripts/dataset/synth_corpus.py \
    --backend cosy --texts <ROOT>/corpus/dsxiaoyi_xval/text.txt \
    --out <ROOT>/dataset/dsxiaoyi_xval
```

`--texts` 必须是与训练集**完全不重叠**的另一批句子（另跑一次 `gen_corpus.py --seed 不同`）。

### 5.4 去重

合成数据理论上不会有重复，但要防两个坑：① 句子表重复；② 归一化后极短片段撞哈希。做法：

```bash
# 按 sha256 去重（保留第一个）
python - <<'PY'
import hashlib,pathlib,collections
d=pathlib.Path(r"<ROOT>/dataset/dsxiaoyi_a3")
seen=collections.defaultdict(list)
for p in sorted(d.glob("*.wav")):
    h=hashlib.sha256(p.read_bytes()).hexdigest()
    seen[h].append(p)
dup=[v for v in seen.values() if len(v)>1]
for v in dup:

print("重复组",len(dup),"删除",sum(len(v)-1 for v in dup))
PY
```

## 7. 验收判据：「像不像晓伊A3」

严格照 `docs/判据手册.md` 的口径。**但这里有一个本课题特有的陷阱，必须先处理。**

### 7.1 ★ 同源自测陷阱（本方案最重要的一节）

如果训练集是 XiaoyiNeural 合成的，测试集也是 XiaoyiNeural 合成的，那么：

- 两者共享**同一个 24 kHz 带宽指纹**（15 kHz 以上数字静音）、同一个房间（无）、同一个前端（无）、同一个语速。
- LTAS 的绝对相关会被这个共同指纹撑满，**Δr 会虚高**，看起来「换得极好」，其实只是「两边都闷」。

实测证据（本次探针 vs 芳乃真人集，都是 48k `0_gt_wavs`）：

| 训练集 | 12–24 kHz 相对 1–4 kHz 能量 | 15–24 kHz |
|---|---|---|
| dsxiaoyi_probe（edge 24k 源） | **−39.8 dB** | **−97.5 dB（数字静音）** |
| fangno（真人 44.1k 源） | **−16.3 dB** | −29.2 dB |

差 23 dB。**这个差距会让跨信道的 Δr 完全失去分辨力**——与芳乃「同游戏原声 Δr≈0 是必然」是同一类病。

**规避办法（三条同时做）**：

1. **参考集自测上限必须重算，不能用芳乃的 0.9863。**
   用训练集里**留出的 25 条 edge 句**算 LOO 自测上限（`r_max`）。本次用 8 条 edge 留出句算得 **0.9686**——比芳乃低，说明这个参考集本身更「散」（TTS 句子间差异比同角色真人录音大）。报告 Δr 时必须写这个数。
2. **交叉验证集必须是异源同音色。** 用 **CosyVoice2 zero-shot** 生成另一批句子（5.3 节）。
   它不是 XiaoyiNeural，带宽、码流、韵律都不同，但它**克隆的是同一个 reference.wav** ⇒ 音色家族相同。
   只有这样测出的 Δr 才不是「共同指纹」的假象。
   ⚠️ 注意 CosyVoice 自己也有漂移（实测 f0 极差 3.65 半音），所以它的 Δr 会偏低，**只能当「下限估计」，不能当主判据**。
3. **必须有一条真人干声通道。** 这是唯一能测「真泛化」的输入：拿芳乃数据集里的真人干声、或《下等马》分离干声，跑换声后看：
   - 音色是否还是晓伊A3（Δr 在同信道内比，参考集用真人干声的 LTAS）
   - **不掉字**（三层 CER）
   - 高频有没有被抹掉（12–24 kHz 能量对比，见 7.3）
   ⇒ 若真人输入下音色还在、但韵律变得「一顿一顿」或齿音发糊，就是同质数据的典型症状。

### 7.2 指标与阈值

| 序 | 指标 | 阈值 | 判什么 | 本次是否可测 |
|---|---|---|---|---|
| 1 | `peak` | < 0.95 | 削波 | ✅ 输入侧已保证（max 0.73） |
| 2 | `dur_ratio` | 0.98–1.02 | 时值保真 | ✅ |
| 3 | 汉字 CER | 与源持平（±0.02） | 有没有掉字 | ✅ 需 whisper |
| 4 | **拼音 CER**（带调，同音字不罚） | 与源持平 | 音素是否走形 | ✅ 主判据 |
| 5 | **声调 CER**（只比调号） | ≈ 0 | 声调有没有被抹平 | ✅ |
| 6 | 声调轮廓 `tone_r` / `tone_rmse` | r > 0.95 / RMSE < 1 半音 | 调型 | ✅ **用 rmvpe + 线性对齐**，不要 pyin、不要 DTW（短句上都会假报警） |
| 7 | Δr | > 0 且**只在同信道内比** | 音色方向 | ⚠️ 见 7.1 |
| 8 | 参考集自测上限 | 必须一起报 | 说明测量到没到顶 | ✅ |
| 9 | `exact_zero_ratio` | ≈ 0 | 要不要补气口 | ✅ RVC 恒为 0 |
| 10 | 12–24 kHz 能量差 | 与真人干声输出比 ≤ 10 dB | **本方案特有：高频有没有被抹** | ✅ 见 7.3 |

**判定顺序**（照手册，不许先听）：电平 → 时长 → CER → Δr → 声调 → 最后才听。
反过来做会陷入「这段有杂音到底是模型问题还是输入电平问题」的死循环。

### 7.3 本方案特有的两条判据

**(a) 带宽指纹检查**
把换声输出与目标参考做同一段文字的谱对比，量 `12–24 kHz 相对 1–4 kHz` 的能量比。
- 若输出 ≈ −40 dB（与训练集一致）⇒ 模型把「15k 以上必须静音」学进去了，输出会闷。这是 24 kHz 源的**物理宿命**，不是训练失败。
- 缓解手段（按性价比）：① 推理后接一段轻量的高频激励（air band EQ / 谐波激励），② 输出侧做 12–20 kHz 的 shelf boost，③ 接受——因为 DS娘 这个音色本身就没有 15k 以上内容，「闷」其实是**符合目标**的。
- **不要**为了骗指标去上采样造高频：那会往 HuBERT 里灌伪谐波。

**(b) 同质腔调检查（韵律泛化）**
拿 3–5 条**真人**、带明显语气起伏的中文干声（不是 TTS），换声后：
- 若源上的语调起伏（f0 半音 std）在输出上被压平（比值 < 0.85）⇒ 模型在用自己的韵律覆盖，是同质数据的典型失败。
- 若出现规律性「每 3.7 s 一个停顿」⇒ 切片边界被学进去了（切片太碎），加大句长（4.2 节）或检查 corpus 里是否有大量 > 7.4 s 的句子。

### 7.4 「像不像」的最终仲裁

客观指标只能**排除明显坏掉的输出**。Δr 判方向、CER 判可懂、tone_r 判声调，**没有一个能判「像不像晓伊A3」**。
最终仲裁 = 盲听 A/B：`原文 edge 合成` vs `RVC 换声输出`，同一句、同一响度（−20 dBFS）、独立文件、独立标注（不许拼接——见交付纪律 D1）。

## 8. 风险与反面情况

按「最可能怎么失败」排序。每条都给**可观测的失败信号**，不许训完自我感觉良好。

### R1. 只会说这一种腔调（最高概率）

**成因**：训练集全部来自同一 TTS、同一风格、同一语速（4.4 字/秒），声学条件方差 ≈ 0。RVC 会把「这种腔调」当成目标音色的一部分。
**症状**：喂真人干声后，音色对了，但
- 语调起伏被压平（f0 半音 std 输出/源 < 0.85）
- 句尾一律下坠、疑问句不上扬
- 齿音段发糊、连读处出现非源停顿

**判定**：7.3(b) 的真人通道测试。**只要真人通道 f0 std 比 < 0.85，就判 R1 命中**，不要拿 edge 通道的成绩辩解。
**缓解**：① 语料里加 `rate` 变化（−15% / −5% / +5% 三档各 1/3），让模型见过不同语速；② 第二轮迭代用「真人读 → RVC 转换」的音频做韵律增广（有误差累积风险，仅当 R1 已确认命中时才做）。

### R2. 24 kHz 带宽宿命（必然发生，只能接受或补偿）

**成因**：XiaoyiNeural 原生 24 kHz。训练目标 15 kHz 以上是 −97.5 dB 的数字静音。
**症状**：输出听感「闷」「像电话」；与真实录音对拍时 12–24 kHz 差 23 dB。
**判定**：7.3(a)。**这不是训练失败**，是声源物理上限。
**注意**：它会让**同信道 Δr 虚高**（7.1），是本方案最容易自欺的一条。

### R3. 音素覆盖的盲区（概率中）

**成因**：357 个音节覆盖 99.7%，但 ① 多音字被 pypinyin 标成常见读音、TTS 却读另一个；② 冷僻音节只在枚举句里出现过一次，模型学得浅。
**症状**：ASR 回读的**拼音层 CER** 集中在少数几个音节上（不是均匀分布）。
**判定**：把 CER 按音节聚合，看错误是否集中在 < 5 个音节。若是，针对性补 20 句即可，不需要重训。
**缓解**：训练前用 `coverage.json` 检查；训练后用 ASR 定位。

### R4. 参考音的身份被误解（方案层风险，概率低但后果重）

**成因**：用户心里的「DS娘 A3」可能指的是 **reference.wav 那一版特定的语调/气质**，而 RVC 学到的是 **XiaoyiNeural 这个 voice 的平均音色**。
**症状**：客观指标全过，但主人听了说「不像，这是另一个人」。
**判定**：盲听 A/B 必须在**同一句**上做，且 A 侧要用 edge 现场重合成（而不是 reference.wav，因为 reference 只有 4 句话的内容）。
**缓解**：训练前先做一次 3 句的「音色确认」——用 edge 现场合成 3 句给主人听，确认「这就是 DS娘 的声音」，再花 2.5 小时训练。**这一步不做，等于赌。**

### R5. 切片碎片污染（概率中，可量化）

**成因**：3.7 s 切片器会留 31–35% 的 < 2 s 碎片。
**症状**：模型在句首/句尾出现「吞字」或短促气声；`exact_zero_ratio` 仍为 0（所以这条查不出来）。
**判定**：统计 `1_16k_wavs` 里 < 2 s 的比例。**> 45% 就要处理**（本次 31%、芳乃 35%，都合格）。
**缓解**：调整语料句长（4.2 节），让更多句子落在 3.0–3.7 s。

### R6. 环境类（低概率，但会浪费一晚）

| 坑 | 症状 | 判据 |
|---|---|---|
| edge-tts < 7.3 | WSS 403，报错像网络问题 | 先跑 `list_voices()`：通了就说明是版本 |
| 代理 | 直连与代理都通，但代理超时会挂 | `--proxy ""` 强制直连 |
| pypinyin 只在 CosyVoice env | 语料脚本在 RVC venv 里跑不起来 | 已内置明确报错与路径提示 |
| preprocess 吞异常 | 退出码 0、切片 0 个 | 已内置「数产物」判据 |
| 忘记 mute 样本 | 气口喷噪 | 已内置自动追加 2 行 |

## 附录 B：跨引擎对照实验原始数据

同 8 句、同参考音色，edge 与 CosyVoice2 各合成一遍：

| 度量 | 值 | 读法 |
|---|---|---|
| 配对 `r(edge_i, cosy_i)`（同文本） | mean **0.9575**，min 0.8976 | — |
| edge 内部不同文本 `r` | mean **0.9392**，min 0.8201 | **同文本跨引擎比同引擎跨文本更"像"** |
| cosy 内部不同文本 `r` | mean 0.9515 | — |
